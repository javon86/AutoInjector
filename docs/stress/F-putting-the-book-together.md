**1. F-16-a ⚠️ — the AI times out → no AI here: the PDF writer is slow (3 s once; every file 3 s), and the PDF writer stuck until removed**

- **Where:** akowe/akowe/autobook.py `_s_export` → akowe/akowe/modules/set_g.py G11 `render_pdf` (no time limit around Akọwe's own PDF writer); the pause words at autobook.py line ~931
- **What happens:** A stuck PDF writer keeps the run working with no time limit; Pause talks about an AI answer. - **How to reproduce:** `cd akowe && python -m tools.stress.run --section F --parts 16 --stress a` (ID F-16-a)
- **Likely cause:** The book PDF is written in-process (no AutoInjector); when the writer is stuck nothing times out. ⏸ Pause shows “Pausing after the current answer…” although no AI answer is awaited, and takes effect only when the writer returns (then Resume finished).
- **Suggested fix:** Say “Pausing after this step…” in steps without AI calls; consider a generous time limit for the file writers with a plain stop (“Making the PDF took too long”). (not implemented)
- **How likely:** unlikely but dangerous
